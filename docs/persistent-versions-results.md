# 岗位存档与变更待办：验证记录

日期：2026-11-05。

## 本轮完成

岗位版本以不可覆盖的快照追加到数据库，保存条件、客户原话、确认人、待确认问题与影响计划。版本冲突由 `(job_id, version)` 唯一键拦截；状态与版本分开保存，勾选待办不改岗位条件。新版本沿用未受影响的任务及完成状态；相关条件被再次修改时重新生成任务，历史任务保留并停止操作。

影响规则只根据已经确认的条件差异运行，生成寻访调整、相关材料复核与客户澄清待办。每项有条件编号、来源版本、逐字原话、前后值；相关材料使用已有示例片段，不代表分析了真实候选人库。不额外调用模型、不自动联系候选人或操作招聘平台。

## 本地验证

- 31 项 JavaScript/API/存储测试通过，包括关闭并重新打开数据库、并发保存仅一份成功、问题摘录校验、项目隔离、未知待办拒绝、过期任务拒绝和未受影响任务状态沿用。
- 浏览器真实模型流程：输入“B 端产品经验改为加分项，但必须主导过产品上线，城市可以放宽。”，生成两项变更和城市待确认问题，确认保存为 v2；刷新后保留五条条件、问题和 v1 历史。
- 进入“影响与待办”，出现五项任务；勾选一项，刷新后显示 1 / 5 已完成；展开来源可看到 B 端从必要条件改为加分项。
- 生产依赖检查未发现已知漏洞。模型密钥仍只从运行环境读取，数据库与 WAL 文件被忽略。
- 窄屏视口设置未实际生效，不将此次截图当作手机布局验收。

## 线上部署与限制

私有网站已部署，D1 绑定 `DB` 已确认存在，迁移创建 `job_versions`、`task_states`、`evidence_reviews` 三张表。发布没有放宽访问范围。

线上浏览器进入了 ChatGPT 登录流程，随后停在 Cloudflare 安全验证页；本轮未完成登录后“保存—刷新”的线上实测，不能把部署成功或表存在当成完整业务验证。数据库尚未承载真实客户资料。本地与线上数据库相互独立，不会自动同步。
