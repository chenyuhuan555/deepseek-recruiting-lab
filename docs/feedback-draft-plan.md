# 客户反馈转岗位变更草稿

2026-11-04

## 本轮范围

沿用当前页面和确认后的大标题、关系图。默认展示客户反馈输入框与“生成草稿”；手动修改保留在折叠区域。草稿列出新增、修改、取消及原文摘录，逐条可编辑和取消勾选。模糊信息单列待确认问题。核对后保存一个新版本。

模型通过同源服务端接口调用 DeepSeek JSON 输出，凭据只在服务端环境中使用，不进入源代码、浏览器或公开仓库。由静态托管迁移为轻量 Worker，保留站点身份和现有私有访问范围；页面数据仍仅保留在当前浏览器会话内存。

## 实施顺序与验证

1. 先写草稿输入/输出边界测试：来源必须匹配原文，修改和取消必须引用已存在的条件，拒绝重复或冲突操作，未提及条件保留，含糊问题不能直接改条件。
2. 服务端提供固定模型接口，限制输入规模与输出、检查请求来源、超时与重复请求，屏蔽上游错误细节；没有配置时明确返回错误，不模拟生成成功。
3. 页面生成中禁用重复提交；输入、项目或岗位版本变化后，不接收旧响应。编辑草稿后取消此前确认。保存沿用现有版本检查，保留问题与审核人。
4. 10 条虚构业务案例先写预期，再进行真实调用；记录耗时、token 和失败。它们验证限定案例，不推算真实招聘准确率或节省时间。
5. 浏览器验证保存、编辑、项目切换、模糊反馈和版本冲突；部署后验证同一接口，发布源码。

## 验收例子

当前 B 端为必要条件、RAG 为加分项、上海为地点要求。输入“RAG 不用卡死，必须主导过产品上线，城市可以放宽”：应只新增明确的上线要求，保留 B 端与 RAG 原分类，城市放宽范围列为问题，不能自动取消上海。

## 边界

字段与摘录校验不证明模型理解正确。浏览器版本冲突不等于数据库事务。此次不增加持久化、账户体系、候选人评分、自动联系或多岗位自主操作。
