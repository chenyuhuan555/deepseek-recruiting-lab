# 客户反馈转岗位变更草稿：本轮实测

日期：2026-11-04。模型：`deepseek-flash`。使用虚构岗位与客户反馈，未使用真实候选人材料。

## 实现了什么

客户原话 → 服务端模型返回结构化草稿 → 校验操作、条件编号与逐字摘录 → 人工编辑/选择 → 确认后生成新版本。含糊和冲突反馈单列问题；相关条件保持原状。输入、项目或岗位版本变化后，不接收旧响应；编辑草稿后需重新确认。

页面保留用户确认的大标题和档案关系图，不添加介绍性副标题和装饰符号。手动修改放在折叠区域。

## 真实模型结果

预先写好 10 条案例和验收条件，再执行真实调用。全部通过；原始的反馈、预期、输出、耗时与 token 见 [实测 JSON](../examples/scoped-memory/evaluations/2026-11-04-live.json)。

覆盖：混合新增与模糊条件、RAG 改必要、明确取消、B 端必要改加分、明确城市范围、薪资模糊反馈、增加年限、不作修改、学历软偏好和冲突反馈。

本轮生成耗时中位数为 939 毫秒；10 次请求共记录 7,365 输入 tokens 与 440 输出 tokens。这是固定输入下的服务端生成记录，不包含人的整理、阅读或修改时间，也没有实际账单金额核对。

例子：“RAG不用卡死，但必须主导过产品上线，城市可以放宽。”返回新增上线经历为必要条件、城市待确认问题；B 端和 RAG 原分类保留，上海条件未被删除。

## 自动检查与边界

23 项 JavaScript/API 测试通过，包含原文不匹配、未知条件删除、重复变更、问题与变更冲突、旧版本、请求格式、跨来源请求、模型未配置和上游错误隐藏。原有 10 项 Python 测试通过。生产依赖检查未发现漏洞。

构建产物检查通过：静态资产与 API 路由可响应，未配置时返回明确错误；实际模型密钥未进入浏览器资源或服务端构建包，只由运行环境提供。

没有人工作业对照，不报告节省时间；10 条固定案例也不等于真实招聘准确率。校验逐字摘录不能证明语义理解正确。岗位数据尚未持久化，不是多用户数据库工作台。模型请求取消不保证上游停止计费，程序不自动重试。

## 页面与部署验证

本地浏览器已实测生成、编辑后重新确认、保存版本、选择部分变更及无效摘录拦截。私有网站已部署，运行环境已配置模型密钥；本轮自动化线上请求被 Cloudflare 访问层拦截，浏览器复查超时，因此尚未确认线上模型调用成功。
