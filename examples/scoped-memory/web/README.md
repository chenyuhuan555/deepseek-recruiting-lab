# 招聘记忆实验室

把客户反馈整理为可编辑的岗位变更草稿，同时体验版本、反馈范围与证据复核。页面案例、客户、顾问和候选材料均为虚构。模型由同源服务端调用，不把密钥交给浏览器。

## 本地运行

需要 Node.js 24。设置服务端环境变量 `DEEPSEEK_API_KEY`，可选 `DEEPSEEK_MODEL`（默认 `deepseek-flash`），然后从仓库根目录运行：

```sh
cd examples/scoped-memory
npm ci
npm start
```

浏览器打开 `http://127.0.0.1:4392/`。本地只监听回环地址。原来的 Python 静态服务器无法处理模型请求。环境变量名称见 [配置示例](../.env.example)，示例文件不会自动加载。

```sh
npm test
npm run eval
```

自动测试使用 Node.js 自带测试器。`eval` 会真实调用 10 次模型并产生相应费用，结果写入 `evaluations/2026-11-04-live.json`。

## 建议的体验顺序

1. 岗位修订：输入客户原话，点击“生成草稿”。核对每条操作、分类与摘录，可以编辑或取消勾选；待确认问题不会自动改变相关条件。
2. 勾选“确认变更”后保存。编辑草稿会取消此前确认；保存成功后才更新页面。并发产生的旧草稿由数据库拒绝，可“重新加载”后核对。“手动修改”仍可独立使用。
3. 反馈范围：切换项目、顾问和日期，观察记录被纳入或排除的原因。历史反馈只作为建议，不改写岗位要求。
4. 证据复核：记录人工结论，再保存一次岗位修改，返回查看“需重新复核”。
5. 影响与待办：查看寻访调整、相关材料复核与客户待确认事项，展开来源查看原话和条件前后值；勾选完成，刷新后检查保留状态。
6. “清空输入”仅清理未保存草稿，不删除岗位与版本。

## 文件与实现边界

- `rules.mjs`：对 [Python 核心规则](../core.py) 的浏览器映射，以及版本绑定的复核状态。
- `data.mjs`：固定虚构案例。
- `app.mjs`：表单、预览、确认、上下文过滤与证据交互。
- `draft-ui.mjs`：草稿编辑和待确认问题。
- `../server/`：输入/输出校验、模型提示、API、本地服务、版本存档与实测案例。
- `tasks-ui.mjs` / `impact.mjs`：待办展示与服务端共用的变更影响规则；不额外调用模型。
- `../drizzle/`：追加式数据库迁移，首次创建岗位版本、待办状态和复核记录表。
- `../worker/` / `../scripts/`：同一 API 的轻量服务端部署与资产打包。构建需在部署目录配置已注册站点的 `.openai/hosting.json`，并移除静态托管字段；密钥由运行环境单独配置。
- `style.css` / `index.html`：响应式界面。
- `memory-map.svg`：用户确认保留的档案关系图，与“招聘记忆，有迹可循”标题共同展示；窄屏采用纵向布局。
- [视觉改版复盘](../../../docs/memory-lab-visual-review.md)：此前设计笔记如何落实到排版、色彩和布局，以及实际检查结果。

岗位条件、待确认问题、版本、待办完成状态和人工复核记录由服务端保存。本地默认文件为运行目录下 `data/workspace.sqlite`，可用 `MEMORY_LAB_DATA_DIR` 指定目录；线上使用 Sites D1 的 `DB` 绑定，两者数据独立。部署清单设置 `"d1": "DB"`，迁移由 Sites 发布流程应用，不在请求里建表。不要提交数据库文件。

首次加载通过幂等初始化写入两个示例岗位，不覆盖已有版本。版本表唯一键防止旧草稿并发覆盖；未涉及条件的待办及完成状态沿用，旧版本任务仅供回看。待确认问题只有相关条件被明确修订时才移除，勾选待办不自动修改条件。

线上沿用原有 owner-private 访问边界；这不是团队权限系统，不支持直接改为公开写入站点。模型接口每个实例限制并行和短时次数，不是跨实例计费上限。证据状态是人工标记，不表示材料已自动核实；这里只引用两个已有示例材料，没有候选人库检索。

模型只返回草稿，不直接保存岗位或联系候选人。引用存在不证明理解正确，仍需人工复核。没有接入 LinkedIn 或 Super-agent；这是独立研究实验。
