# 招聘记忆实验室

把岗位版本、带范围的反馈和证据复核变成可以动手操作的工作台。无依赖静态页面，全部案例、客户、顾问和候选材料均为虚构。

## 本地运行

在仓库根目录运行：

```sh
python -m http.server 4392 --bind 127.0.0.1 --directory examples/scoped-memory/web
```

浏览器打开 `http://127.0.0.1:4392/`。需要现代浏览器支持 ES modules 和 structuredClone，不能直接双击 HTML。

```sh
node --test examples/scoped-memory/web/rules.test.mjs
```

规则测试使用 Node.js 自带测试器，无需安装依赖。

## 建议的体验顺序

1. 岗位修订：选“增加上线经历”，查看变更，核对并确认。检查其他条件是否保留。
2. 再次预览，点击“模拟版本冲突”，勾选“确认变更”后保存，观察旧版本冲突。重新查看变更后可以提交。
3. 反馈范围：切换项目、顾问和日期，观察记录被纳入或排除的原因。历史反馈只作为建议，不改写岗位要求。
4. 证据复核：记录人工结论，再保存一次岗位修改，返回查看“需重新复核”。
5. 点击“重置”恢复初始案例。

## 文件与实现边界

- `rules.mjs`：对 [Python 核心规则](../core.py) 的浏览器映射，以及版本绑定的复核状态。
- `data.mjs`：固定虚构案例。
- `app.mjs`：表单、预览、确认、上下文过滤与证据交互。
- `style.css` / `index.html`：响应式界面。
- `memory-map.svg`：上一版原创主视觉，保留为设计记录，当前界面不再展示。
- [视觉改版复盘](../../../docs/memory-lab-visual-review.md)：此前设计笔记如何落实到排版、色彩和布局，以及实际检查结果。

数据仅在当前页面内存中，刷新、关页或重置会清空。没有后端、真实身份认证、权限隔离、数据库或并发事务。旧版本冲突由当前页面的模拟操作产生，不是多用户数据库并发测试。证据状态是使用者的人工标记，不表示材料已自动核实。

不调用模型、LinkedIn 或其他招聘服务，不解析自由文本，不自动推荐或联系候选人。它是独立研究演示，并非 LinkedIn 官方产品或其内部系统的复刻。
