# 岗位版本与记忆范围：最小代码示例

状态：独立、内存中的规则演示；没有接入现有应用。只使用虚构数据，无外部依赖和模型调用。

从仓库根目录运行，要求 Python 3.10 或更新版本：

```sh
python -m unittest discover -s examples/scoped-memory -p 'test_*.py' -v
```

- [core.py](core.py)：不可变岗位快照、经审核的变更应用、记忆范围与有效期筛选。
- [test_core.py](test_core.py)：模拟客户补充要求、修改或取消条件，以及错误范围和过期反馈。
- [完整实现思路](../../docs/scoped-memory-implementation.md)：数据库事务、人工审核、证据卡和模型接入边界。

2026-11-03 在 Python 3.14 的本地环境运行：10 项测试通过。首次运行时实现尚未存在，测试导入失败；补充实现后再次运行通过。

## 能说明什么

1. 补充“主导过上线”时保留原有 B 端与 RAG 条件。
2. 经审核的 preferred 分类在版本更新中不被程序改为 required。
3. 旧版本不能直接覆盖当前快照。
4. 其他客户、过期、未经确认和未知范围的记录不会被检索为有效上下文。

## 不能说明什么

示例不解析自然语言，不判断模型给出的条件分类是否正确，不验证确认人的真实身份，不提供账户或租户隔离，也不持久化数据。调用方传入的是可信且已授权的当前快照；生产数据必须在服务端认证、权限过滤与字段验证后进入这些规则。

`expected_version` 的内存检查不等于数据库并发控制。`confirmed_by` 非空也不等于获得授权。来源摘录存在不等于业务结论已经核实。
